# Frontend rules — Next.js as a static PWA

<!-- Source: 03 §6–§8, §14. Loads when Claude reads or edits a file under frontend/. -->

## A static app (ADR-0016)

- `output: 'export'`: plain files, no Node server in production.
- Every page is a client component. No server components at runtime, no server actions, no middleware, no route handlers, no image optimisation (`images.unoptimized`).
- A file that asks use-intl for words (`useTranslations`) starts with `"use client"`. The area layouts are built as server components, and a part they import without the line stops `next build` at the first page in an area ("createContext is not a function"); no Vitest test sees it, so `use-client.test.ts` reads the files (UI-1).
- No dynamic `[id]` pages for records: use a query string (`/sales/view?id=…`). The page reads it with `useSearchParams()` inside `Suspense`, which the build needs, and hands the id to its screen, so a test gives the screen an id; outside a running app the hook gives `null`, though its type says otherwise (`/workers/view/?id=…`, PPL-6).

## Two data paths — the main rule

- **Counter screens** (`src/app/(counter)/…`: sale, payment, repayment, quick customer, drawer, clock-in) read Dexie with live queries and save documents with `saveDocument()`. They never call the API, and they behave the same online and offline. A save tells the sync by itself; *Tuma sasa* asks for one with `askToSendNow()` (`src/offline/sync/asks.ts`, which calls nothing). The sync runs beside every page, at its own moments (`src/offline/sync/triggers.tsx`, in the root layout), one tab at a time (SYNC-9).
- **A busy counter** (SYNC-13): a counter screen with work open, a sale with lines in it, calls `useCounterBusy(true)` (`src/offline/busy.ts`) while it is: the *Toleo jipya* bar stays hidden, in every tab, until no screen is busy, as switching versions reloads the page. A one-tap screen, as the clock-in, has nothing open to lose.
- **Who is at the counter** (SYNC-11): a counter screen reads `usePersonAtCounter()` (`src/features/login/at-the-counter.ts`), a note the home page writes in the tab's memory, never `me`. The frame (`src/app/(counter)/counter-frame.tsx`) shows a screen only to someone it names, and its *Toka* asks the home page to log them out (`askToLeave`). A record the server refused shows with `NeedsAttention` (`src/app/(counter)/needs-attention.tsx`): a new kind of record adds its name to `whatItWas`.
- **Office screens** (`src/app/(office)/…`) use TanStack Query and the typed client in `src/api/client.ts`, through `answerOf()` (`src/api/refusal.ts`), which throws a refusal so TanStack sees it; `ApiErrorAlert` shows it. Offline they show *Inahitaji mtandao*. Each read is asked in the part of the screen that is always on the page, and its answer handed down, as the values that part reads itself (`data`, `error`, `isPending`), never TanStack's whole result: TanStack draws a part again only when a value that part read changes, so a result handed down and read only by a form that opened later kept showing an answer on its way after it had failed (PPL-8's review, `RolesRead`): a part shown only once a wait ends, that asks a read itself, mounts on a failed read and asks again (TanStack's `retryOnMount`), which brings the wait back and takes the part away, round and round, many times a second (PPL-6's list; the settings page, #272). The wait line waits on `isPending` alone, the store's own tries included, or the page shows nothing for those seconds; a form hangs on who is here, never on a list's wait, which comes back at each new read of a list that never answered. A copy from another answer, shown while a read goes (a worker from the list), is `placeholderData`, never `initialData`: TanStack keeps `initialData` as the state a reset goes back to, so `forgetTheLastPerson` would put the last person's copy back for the next (PPL-6's review).
- A lint rule refuses `src/api/`, `@tanstack/*`, `openapi-fetch`, `fetch`, `XMLHttpRequest`, `WebSocket`, `EventSource` and `navigator.sendBeacon` in `src/app/(counter)/` (`import-rule.test.ts`); tests there may watch `fetch`, never import `src/api/`. It reads a screen's own code only: a shared part that calls the server, imported by a counter screen, and a dynamic `import()` of a package, need review to catch them (UI-2). Screens that log in call the server, so they live outside `(counter)/`. The store of server answers is shared by everyone on a device: empty it at each login, logout and quick switch with `forgetTheLastPerson` (`src/api/query-client.ts`), never `clear()`, which leaves a screen on show with the last person's answer (UI-4); it keeps a change still on its way in its place in the queue, as one dropped goes on trying all the same (SYNC-10). Every change waits in one queue (`CHANGES_IN_ORDER`, the store's default scope), sent one at a time in the order made, offline too, so a logout always goes after the changes made before it; a password form's change sets `gcTime: 0`, so no password stays in the store (UI-5).
- allauth's password routes (`/_allauth/browser/v1/`) are outside the API's description: call them with `callAllauth` (`src/api/allauth.ts`), which sends the CSRF token, throws `NoConnection` with no answer, and reads allauth's own answer into the same `ApiRefusal`, so `ApiErrorAlert` and `apiFieldMessages` show it. A route's bare 401 or 409 is named by the form that calls it (UI-5).

## Numbers and text

- Money and quantities go through `src/lib/decimal.ts` (big.js); round only with `src/lib/rounding.ts`. Both pass `shared/test-vectors/`. No plain `number` arithmetic on money.
- Whoever is logged in sees their own language and font; nobody, the laptop's own (UI-9). A screen that learns who is here calls `useFollowThePerson(here)` (`src/features/people/follow-the-person.ts`) with the person it shows, as both frames do: it opens their language with `setPersonsLanguage`, in memory only, and sets their font on `<html>` (`data-font`). `setLanguage` is the laptop's own, from the bar's button, which shows only while nobody is logged in (Jack's choice). A person's choices change only in *Mipangilio yangu* (`PATCH /api/auth/me/settings/`).
- Times of day are shown with `formatTime` (`src/lib/format.ts`): `07:55`, 24 hours, in the shop's zone, never Swahili time, and through the books' `attendance.timeOfDay` with `dayPart`, which adds *asubuhi*, *mchana*, *jioni* or *usiku* in Swahili, "saa 07:55 asubuhi" (Jack, SYNC-11); dates with `formatDate`, `13/11/2026`.
- Money is shown with `formatMoney` (`Intl.NumberFormat('sw-TZ')`, TZS without decimals); stock with `formatStock`, in each book's order: "mifuko 26 + kilo 35.5" in Swahili, "26 mifuko + 35.5 kilo" in English (`src/lib/format.ts`).
- No visible string literals: every string is a use-intl key (`useTranslations()`, ADR-0040) in `messages/sw.json` and `en.json`, Swahili first; lint rules refuse a word typed into a screen or into `aria-label`, `aria-description`, `placeholder`, `title` or `alt`, and `language.test.tsx` opens every page in English. API error codes map to translated messages: `errors.<code>` in both books, nested by the code's dots (`errors.pin.locked`), turned into its sentence by `codeMessage()` (`src/i18n/codes.ts`, outside the counter lock, so sync's codes can use it too); office screens show a failed call with `useApiErrorWords()` (`src/api/errors.ts`). `errors.test.ts` lists every code the API sends: a new code adds its line there and its two sentences (UI-2). Tests render a screen with `src/test/render.tsx`, which gives it the word books.

## Generated and vendored code

- `shared/openapi.json` and `src/api/schema.d.ts` come from `pnpm gen:api` — never edit them; commit both. CI fails if either is stale (`pnpm check:api`, and a backend test).
- `src/components/ui/` comes from shadcn (`pnpm shadcn add <name>`, a download: ask first). Never edit shadcn's files there (`guard.py` refuses it); Prettier skips the folder, and its `README.md` is its header.

## The look (ADR-0039)

- Screens use only our pieces in `src/components/design/` (Button, ButtonLink, TextLink, Field, PasswordField, Input, Label, Choice, Card, Alert, SideBand, TopBar, PageHeader, Tabs, Sheet). ButtonLink is a real link with the button's classes, as Base UI's button must not be a link; TextLink is a link in words, the text's colour underlined, as a worker's name on *Wafanyakazi* (PPL-6); Choice is a big row per option, over shadcn's radio-group (UI-3), and a row may name its own `lang` and `font` (UI-9), and show a `picture` before its words, hidden from a screen reader, as a side's band (SHOP-4). Every password box is a PasswordField, whose eye shows and hides what is typed, in Field's `end` slot (UI-5). Only `components/design/` imports `components/ui/`: a lint rule refuses it anywhere else (`import-rule.test.ts`).
- Every page reached from another starts with `PageHeader` (`page-header.tsx`), and so does every new one (Jack, OPS-13): the office screens (*Mipangilio ya duka*, *Vifaa*, *Hali ya vifaa*, *Wafanyakazi* and a worker's own page, whose `fallback` is the list, and *Mipangilio yangu*), the login pages, the counter's (*Mahudhurio*, *Kompyuta hii*) and *Sajili kifaa hiki*; `/design` wears it too. The back arrow sits on the far left, *Rudi ulipotoka* to a screen reader, then the title, its one `<h1>`, and the page's intro under it, in the pale grey. A page's one main button goes at the title row's far end (`action`), as *Wafanyakazi*'s *Ongeza* (UI-11). It is the screen's only way back: no *Rudi* button at the bottom. The arrow goes back (`router.back()`) only when the tab's note says the person moved between the app's own pages (`src/components/in-app-moves.tsx`, in the root layout, kept in `sessionStorage`), by a move that added a page to the tab's history: a redirect (`router.replace`) is none, as the page before it may not be ours (OPS-13's review); else, as from a bookmark or Chrome's new tab, to `fallback`: the office's home unless the screen names another (*Mipangilio yangu* names the person's home; `/login/`, the counter's pages and *Sajili kifaa hiki* name `/`; *Umesahau nenosiri?* and the reset link's page name `/login/`). The two home pages, `/` and the office's, have none, as the arrows lead there. The PIN pad, a step inside `/`, wears it too: its arrow goes back to the tiles (`onBack`), and is held while a PIN is on its way (`backDisabled`), as `/login/`'s is while a login is. A page on its way out by itself leaves the arrow out for that moment, its title kept (`arrow={false}`): the clock-out's goodbye. A screen that focuses its title as it opens passes `headingRef`.
- A short action (pick, type why, save) opens in a `Sheet` (`sheet.tsx`) over its own page, from the bottom, with *Ghairi* and the main button side by side at its foot (Jack, ATT-6): the screen keeps whether it is open, gives the title, the main button's words and the form, and sets `busy` while the action is on its way, which holds both buttons and keeps it open; a refusal shows inside it. Only *Ghairi* and Esc close it, never a tap on the dimmed page, which would throw away what was typed (Jack, UI-10). Its main button names the action (*Simamisha*, *Weka PIN*), red (`actionKind: "danger"`) for one that takes something away for good; the screen draws the sheet only while it is open, so its boxes go with it, and keeps the button that opened it on the page under it; the sheet alone moves the keyboard as it closes, to what the screen names (`finalFocus`): the done line after a change, else the very button that opened it, as Base UI moves it a moment after the sheet goes, overruling any move of the screen's own (UI-10's review). A long form keeps its own page, with PageHeader's arrow and no *Ghairi*: its *Hifadhi* goes where the arrow goes (`mayGoBack`, else `router.replace`), and its arrow's fallback takes its place too (`fallbackInPlace`), so the form never stays in the tab's history (UI-11's review); and the line that says what it did shows on the page it lands on, from a note in the tab's memory, read once (UI-11, *Wafanyakazi*'s four forms, `features/workers/page-news.ts`); it opens on the record's own read, never a list's copy shown meanwhile.
- A long page is cut into `Tabs` (`tabs.tsx`), as *Mipangilio ya duka* is: the screen gives a list of sections (`value`, `label`, `content`), and a new section is one more item. The row scrolls sideways and sticks to the top; every section stays mounted, hidden while closed, so a half-filled form survives a switch; the open tab lives in the address (`?tab=money`), through `useTabInAddress` (`src/components/tab-in-address.ts`, CTRL-4), replaced, not pushed, so the back arrow leaves the page; it is written with `history.replaceState(null, …)`, never Next's own state, which would hide the new address from its router. A test reads a closed tab's contents with `hidden: true`, or opens its tab first, as a person does.
- A new shadcn part gets a piece of ours in `components/design/`, with its test, before a screen uses it. Read what `shadcn add` changed: if it writes greys or chart and sidebar tokens into `globals.css`, `tokens.test.ts` fails — remove them.
- A photo picked on an office screen (PPL-9, *Picha*): a hidden file box behind a Button, emptied at each pick, with `capture` to ask a phone for its camera; `shrinkFile` (`src/lib/shrink-photo.ts`) before anything is shown or sent; the bytes as the whole body, past the client's JSON (`bodySerializer`). A photo the server keeps opens from `photoAddress` (`src/lib/photo-address.ts`); a worker's photo on a laptop shows from the laptop's own copy, with `TileFace` (`features/login/tile-face.tsx`), which lets go of the address it made as it goes (PPL-14).
- Colours, corners and heights come from the tokens in `globals.css`, never a value of a screen's own. Heights are written `h-(--control-big)`, a spelling `cn()` knows is a height.
- Focus rings at full strength (`ring-ring`, never `ring-ring/50`); on green, the ring is white: anything green uses `ON_GREEN` from `top-bar.tsx`, which sets `--ring`, and only the button's `bar` kind sits on it (UI-1).
- Counter, office and setup screens live in `src/app/(counter)/`, `src/app/(office)/` and `src/app/(setup)/`, whose layouts wrap them in `AppFrame` (the top bar and the page's one `<main>`): a screen there doesn't write its own `<main>`. The setup area holds what a device does before it belongs to a shop (Sajili kifaa hiki); it calls the server, so it is outside the counter lock (UI-3). The home page `/` of a registered device is the PIN login (`src/features/login/at-the-device.tsx`), in AppFrame's `login` area, whose bar names the person and the side they work on (UI-4). Its tiles read the laptop's copy of the staff, so they show offline (`staff-picker.tsx`); with no network, no answer, or a logout not heard yet, the PIN is checked on the laptop (`checkPinOffline`, `src/offline/pin.ts`), and someone let in that way is `useOfflinePerson()` (`src/features/login/offline-session.ts`), a session in the tab's memory only, which a block, a sync's suspension or a new PIN ends (SYNC-10). The password pages live in `src/app/(login)/` (login, forgot password, the email link's page), in the same area. The office layout is `OfficeFrame` (`src/features/office/office-frame.tsx`): the person, their shop and *Toka* in the bar, anyone not logged in sent to the way in, a registered laptop's idle lock, and *Chagua nenosiri lako* in place of the screen for a temporary password; a new office screen adds its button to the office's home page (`office-home.tsx`) (UI-5). *Mipangilio yangu* (`/my-settings/`) has a button there for everyone, and on the PIN home's welcome (UI-9).
- The device knows itself through `src/features/devices/this-device.ts` (its saved copy, `mpc.device`, which never calls the server, so any screen may read it) and `device-check.tsx` (which asks the server, on every page). A `device.blocked` from any call through the store locks the app (`DeviceLock`), so send every screen's call through TanStack Query; sync's pull and push run outside the store, so each keeps it through its place (`src/offline/sync/page-place.ts`); the service worker's push, which has no `localStorage`, leaves a note in the shop's database that the page takes (UI-3, SYNC-7 to SYNC-9, SYNC-16).

## Screens

- Laptops are keyboard first (`/` focuses search, Enter adds); phones get big tap targets and a numeric keypad for cash and kg.
- Budgets: counter code under 300 KB compressed, per counter page, checked after the build by `frontend/scripts/counter-budget.mjs` in `make check-frontend` (SYNC-11: `/attendance/` 234.6 KB, nearly all shared); confirming a sale under 0.3 s; search under 50 ms for 5,000 products.

## Tests and commands

- Vitest + Testing Library + fake-indexeddb, next to the code (`*.test.ts(x)`); Next.js's router is a stand-in in every test (`src/test/router.ts`, set up in `vitest.setup.ts`), which a test reads to see where a screen sent the person (UI-5); Playwright in `frontend/e2e/`, against the backend image — it can switch the browser offline.
- Scripts: `pnpm dev`, `pnpm build`, `pnpm test`, `pnpm lint` (ESLint with no warnings allowed, then a Prettier check), `pnpm format`, `pnpm typecheck` (REPO-3); `pnpm gen:api` and `pnpm check:api` (UI-2); `pnpm e2e` (UI-6).
